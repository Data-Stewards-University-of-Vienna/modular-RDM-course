# Data Organization

Objectives
--------------------

Learners will be able to:

* describe the relevance of file and folder naming conventions 
* state criteria for developing file and folder organization schemas
* develop naming conventions
* apply naming conventions to their own (and collaboratively) used research data
  
Introduction
--------------------

**The Challenge**

Data flows from raw data to results, via tables and figures to communication outlets. We know there will be LOTS of files, that they can change over time (versions), have relationships to each other, and will be required to be understandable as the basis of our findings and publications.

**The Solution**

Just like in a well-sorted kitchen, it will make your work and collaboration a lot faster if it is clear where to find things. This means that a file name and location need to be informative even before you open it. The more self-explanatory they are, the better.

There are two perspectives to keep in mind when to judging the quality of file names: 1) Can you decide whether you want to open a folder or file, i.e., whether is it what you are looking for? And 2) Can you sort a file into a folder so you will able to find it again, i.e., do the folders match the natural categories of your work?

Organizing files makes them more findable and accessible (feeding into the FAIR principles) and enable 'someone' to understand what you did -- that 'someone' is usually you in 6 months' time.

**The Imperative**

In order to get to the solution, you need a plan and establish naming and structuring systems, document them, and make sure to use them consistently.

Any system is better than none!

How to Name Files and Folders
--------------------

Naming files and folders consistently will ensure a system is in place when new files need to be added to ongoing projects, but also to be able to find things again when returning to (potentially long finished) projects and files within those projects. A proper structure to naming conventions allows for easier and more efficient retrieval, tracking, and sharing of data.

Here are some guidelines for creating effective file names:
* **Give a unique name:** Each file should have a unique name that distinguishes it from other files.
* **Use elements essential to identify the file:** Include elements that are essential to identify the file, such as the name of the project, experiment, or subject.
* **Avoid long names, remove unnecessary elements:** Long file names can cause problems in storage, transfer, and handling of data. Keep file names concise and avoid unnecessary elements such as redundant information or irrelevant details.
* **Use ISO8601 standard for dates:** Using the ISO8601 standard for dates (i.e., YYYYMMDD) allows for consistent and chronological sorting of files.
* **Use ascending decimal version numbers:** When versioning files via filename, use ascending decimal version numbers (e.g., v1.0, v1.1, v1.2) to keep track of changes and updates.
* **Use alphanumerical characters only:** To ensure compatibility across platforms and systems, only use alphanumeric characters (A-Z, a-z, 0-9) in file names.
* **Do not use special characters:** Avoid using special characters in file names, as these can cause errors or conflicts in some systems.
* **Use underscores for separation:** Instead of using spaces in file names, use underscores ("_") for separation.
* **Do not alter or remove the extension of a file:** File extensions indicate the format and type of the file. Do not alter or remove the extension of a file, as this can cause errors or prevent the file from being recognized by certain programs or systems.
* **Be consistent and reach consensus:** It is essential to be consistent in how you build up names and ensure that there is consensus among all team/project members to avoid confusion and ensure understanding of naming conventions used for the project.
* **Document your naming scheme:** In order to ensure long-term success and facilitate comprehension of your consistent naming scheme, it is advisable to thoroughly document it. This documentation should be structured in a manner that enables people unfamiliar with your data to comprehend it easily.

For naming folders, similar guidelines also apply, though they are usually more general in nature than the names of individual files. Here, you should also keep in mind that the structure of the folders matters. A well-designed folder structure can help you quickly and easily locate the data you need, saving you time and effort. A clear and consistent folder structure can also help you collaborate effectively with other members of your research team. By establishing a standardized approach , everyone involved can easily access and understand your data.

* **Design clear folder structures that align with the project:** Before starting your research, plan out a folder structure that aligns with the objectives and goals of your project. This structure should be intuitive, easy to understand, and should follow a logical sequence of stages.
* **Use the same structure for different locations:** If you are working on the project across multiple computers or with different team members, ensure that the same folder structure is used across all locations.
* **Use max. 4 levels of folders:** Keep the folder structure as simple as possible by limiting the number of levels to a maximum of four. This will make it easier to navigate and manage.
* **Classify folders according to different project stages (raw, processed, analyzed):** Classify the folders based on the different stages of the project, such as raw data, processed data, and analyzed data. This will help you to organize the files based on their current stage of completion and make it easier to locate the data when needed.
* **Document the naming scheme and folder structure:** Once you have finalized the folder structure, document it clearly to avoid confusion and ensure that all team members are on the same page.

Types of Data to Organise
--------------------

Data can exist in different forms, and it is important to keep them separated. Generally speaking, data can be divided into three different types:
* **Raw data:** The original data that has not yet been processed, cleaned, or analysed. It is unique and lossless, meaning it contains all the information collected by the instrument used to capture it. Raw data is typically in its original form, without any modifications, and may be in various formats, such as text, numerical, audio, or visual.
* **Processed data:** Data that has already had some form of alteration or cleaning, such as normalisation, removal of outliers, filled-in missing data, or any other modification to make it easier to work with or more suitable for specific analysis purposes. Processed data is typically in a format that is easier to work with, analyze, and visualize.
* **Analysed data:** Can also be referred to as output data. This is the data that has been processed, interpreted, and analysed. This stage often involves using statistical or other analytical techniques to extract insights or knowledge from the data. Analyzed data is often presented in the form of graphs, tables, or other visualizations that help to communicate the findings. This is often the type of data used in journal publications.

When preserving data, the raw data is often the most valuable one. Raw data is unique and should be safeguarded to prevent loss. It should also be secured to prevent unauthorised access or modification through the use of pass word protection, encryption, or other security measures. While working on a dataset, it is useful to create a copy of the raw data as a working copy for processing and analysis. This will ensure that the original raw data does not accidentally get overwritten or edited without awareness.
